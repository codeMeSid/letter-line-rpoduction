## Decisions and rationale

- **Delegation.** The bottle factory was built by a Sonnet implementer subagent. An Opus reviewer and a general-purpose visual QA agent then checked it, so that the main session's limited context was preserved.
- **11 product stages instead of the spec's 8.** The stages are `tub, batch, mixed, melted, gob, parison, bottle-hot, bottle, filled, capped, labelled`. The factory host shows `shape(job.stage, 1)` between stations, so the silos, mixer and furnace each needed their own output stage to keep `shape(stage, t)` continuous across hand-offs (`shape(S_k, 1) ≡ shape(S_{k+1}, 0)`). A test checks this continuity. The reviewer accepted it.
- **Morph targets.** The base geometry is the finished bottle, and the gob and parison are the two morph targets. This keeps the shelf bounds (computed from the base geometry) correct. The reviewer confirmed that the weights land on gob, parison and bottle at morph 0, 1 and 2.
- **Label.** The glyph on the label is a bent `letterGeometry` from `engine/glyphs.ts`, and the label band is a partial draw-range cylinder. A `CanvasTexture` was not used because it cannot run in the node-environment vitest tests, and project rules forbid fonts and `TextGeometry`.
- **Letter marks.** The `letterMarks` options emboss, label and cap are honoured; `shape` is ignored for the bottle.
- **Inspection.** The inspection station returns `reject` only when `job.defect` is set. Nothing in the codebase currently sets `defect`, so it never rejects in play. This was accepted as a known gap.
- **Labeler particles.** The labeler emits no particles, while the other 11 processing stations do. The "job makes particles" test is relaxed for it.
- **Shared code extraction.** `factories/letter/stations/common.ts` was moved to `factories/shared/stationKit.ts`, and the old file now only re-exports it so existing letter imports keep working. The rail robot was generalised into `factories/shared/railRobot.ts` as `railRobot(id, beltTip, shelfTip)`, and both factories' `robot` stations wrap it. The reviewer confirmed the letter robot refactor is identical code and that `RAIL_BEHIND` is still re-exported.
- **No bench views for the bottle.** `components/Bench.tsx` has about 10 letter-specific references, so adding bottle views was not cheap and was deferred.
- **Review fix 1 (IS machine rotation).** In `factories/bottle/stations/isMachine.ts` line 118, `product.root.rotation.y` was left at 2π after the invert swing. That looks identical to 0 but is leftover state. It is now `product.root.rotation.y = swing < 1 ? th : 0;` with a comment.
- **Review fix 2 (robot grip heights).** In `factories/bottle/stations/robot.ts`, the grip heights `28, 28` gripped the bottle at its shoulder. It is now `railRobot('bottle-robot', PUCK_T + 15, 15)` with `PUCK_T` (= 3) imported from `../product`. The belt tip is mid-body above the puck. On the shelf, `place()` drops the content by `PUCK_T` and hides the puck, so the shelf tip is 15. The reviewer had suggested `PUCK_T + 15` for both; I chose 15 for the shelf because of that puck drop. Neither value has been verified by eye.
- **No commit without an explicit request.** The user's global rules say commits happen only when the user asks, so the work was left uncommitted and the user was asked.
